# Landing Page SQL Demo — Maintenance Guide

The landing page at `source/index.md` features an interactive tabbed demo showing C# LINQ code alongside the real SQL generated by linq2db. This document explains how to maintain and extend it.

## Architecture

- **C# side**: Hand-written syntax-highlighted HTML using `<span>` classes (`code-keyword`, `code-type`, `code-string`, `code-number`, `code-comment`)
- **SQL side**: Real SQL output generated by linq2db's `ToSqlQuery()` API, then hand-formatted with the same span classes
- **Tabs**: Pure CSS — hidden `<input type="radio">` elements + `:checked` sibling selectors in `main.css` (no JavaScript)

## How to generate SQL for a new or updated tab

### 1. Copy `SqlDemoGenerator.cs` to linq2db Tests.Playground

```bash
cp tools/sql-demo/SqlDemoGenerator.cs ../linq2db/Tests/Tests.Playground/SqlDemoGenerator.cs
```

### 2. Edit the test to add/modify queries

The file defines entity models (`Product`, `Category`, `Order`, `OrderItem`) and test methods that generate SQL using:

```csharp
var sql = query.ToSqlQuery(new SqlGenerationOptions { InlineParameters = true }).Sql;
Console.WriteLine(sql);
```

- SQLite connection (`CreateSQLiteConnection()`) works for most queries
- Merge requires SQL Server — use `[IncludeDataSources(TestProvName.AllSqlServer)]` attribute
- TempTable creates DDL (side effects), so its SQL is documented manually on the landing page

### 3. Run the tests

```bash
cd ../linq2db
dotnet test Tests/Tests.Playground/Tests.Playground.csproj \
  -c Debug -f net10.0 \
  --filter "FullyQualifiedName~SqlDemoGenerator" \
  -v n --nologo 2>&1 | grep -A 50 "=== "
```

This prints the SQL for each test. Copy the output.

### 4. Copy the test file back to docs for reference

```bash
cp ../linq2db/Tests/Tests.Playground/SqlDemoGenerator.cs tools/sql-demo/SqlDemoGenerator.cs
```

### 5. Update the landing page

Edit `source/index.md`. Each tab consists of:

```html
<!-- Tab N -->
<div class="demo-panel demo-panel-N">
<div class="demo-split">
<div class="demo-pane">
<div class="demo-pane-label">C# LINQ</div>
<pre class="demo-code">...syntax-highlighted C# here...</pre>
</div>
<div class="demo-pane">
<div class="demo-pane-label">Generated SQL</div>
<pre class="demo-code demo-sql">...syntax-highlighted SQL here...</pre>
</div>
</div>
</div>
```

### Adding a new tab

1. Add a new `<input type="radio">` with id `demo-tab-N`
2. Add a `<label>` in the `.demo-tabs` div
3. Add a `.demo-panel-N` div with the content
4. Add CSS selectors in `source/templates/custom/public/main.css`:

```css
#demo-tab-N:checked ~ .demo-tabs label[for="demo-tab-N"],
/* ...add to the existing comma-separated list... */

#demo-tab-N:checked ~ .demo-panels .demo-panel-N,
/* ...add to the existing comma-separated list... */
```

## Syntax highlighting classes

| Class | Color | Used for |
|-------|-------|----------|
| `code-keyword` | Purple (#c792ea) | C# keywords, SQL keywords (SELECT, FROM, WHERE, etc.) |
| `code-type` | Blue (#82aaff) | Type names (Product, DataConnection), SQL functions (COUNT, SUM) |
| `code-string` | Green (#c3e88d) | String literals |
| `code-number` | Orange (#f78c6c) | Numeric literals |
| `code-comment` | Gray (#676e95) | Comments (// and --) |

## Important: blank lines in `<pre>` blocks

DocFX's Markdown processor converts blank lines inside `<pre>` into `<p>` tags. Use `&#10;` (newline entity) instead of actual blank lines to create visual spacing inside `<pre>` blocks.
